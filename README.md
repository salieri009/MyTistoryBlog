# Salieri Index — Tistory skin

글자가 먼저인 담백한 티스토리 스킨입니다.
블로그 주소: https://igewaedam630.tistory.com/

- 연도별로 묶인 글 목록 (날짜 · 제목 · 카테고리 · 썸네일), 홈 소개 문장과 프로필
- 글 상단 카테고리 경로, 카테고리 페이지 하위 카테고리 칩
- `[과정] N일차 :: 주제` 형식의 제목을 시리즈명과 주제로 나눠 표시하고, 글 끝에 같은 시리즈 글 목록
- 글 끝 다음 걸음
  - 시리즈 글이면 "이전 편 / 다음 편", 글 맨 위에도 ‹ › 화살표
  - **함께 읽을 글**: 글의 주제(태그)마다 칩과 관련 글 3개. 태그가 제목·소제목·코드·본문 중 어디에 나오는지로 주제의 비중을 매기고, 독자가 오래 읽은 섹션의 주제를 먼저 보여 줌
  - 시리즈 목록에 이 브라우저에서 읽은 편 표시("읽음", "N편 읽음"), 최신 편에서는 구독 안내
  - 목차 아래 "다음에 읽기" (다음 편 > 독자 주제의 관련 글 > 다음 글 > 같은 카테고리)
  - 푸터 목록에서 이미 나온 글 빼기
- 다시 온 방문자
  - 지난 방문 이후 "새 글" 표시
  - 읽은 글 흐리게
  - "이어 읽기"
  - 홈 길잡이(이어 읽기 · 최근 시리즈)
  - 기록은 방문자 브라우저에만 저장합니다
- 입력하는 대로 보이는 검색 미리보기, `/` 키로 검색, 결과가 없을 때 많이 읽힌 글과 카테고리
- 긴 글을 위한 목차(레일·모바일 시트), 읽는 시간, 소제목 링크 복사, 코드 복사·긴 코드 접기, 표 가로 스크롤
- 인용 스타일 1·2·3 = 핵심 · 트러블슈팅 · 해결/회고
- 기본 편집기에 붙여 넣은 마크다운(제목·목록·표·코드·인용)을 자동으로 렌더링하고, 코드 블록에 넣은 마크다운 표는 실제 표로 변환
- 티스토리 댓글·명함·공감 버튼을 스킨 색과 다크 모드에 맞춤
- 불러오는 동안 화면이 밀리지 않게(CLS) 처리
- Salieri 다이어그램 팔레트, 다크 모드 (기기 설정 + 토글)
- 의존성 없음. 모든 내용은 티스토리 치환자와 블로그 자체 페이지에서 옵니다

디자인 결정은 [DESIGN.md](DESIGN.md), 제품 맥락은 [PRODUCT.md](PRODUCT.md)에 있습니다.
이전 버전(이정표)은 태그 `signpost-v1`, 비교 시안은 `node dev/proposals/build.mjs`로 다시 만들 수 있습니다.

## 로컬에서 보기

```bash
npm run dev       # http://localhost:4173 — 샘플 데이터로 렌더링, 파일 저장 시 자동 새로고침
npm run check     # 렌더링 + 치환자/옵션/커버 정합성 검사
npm run package   # 검사 후 dist/salieri-index-skin.zip 생성 (티스토리 업로드용)
bash dev/check-contrast.sh   # 모든 미리보기 페이지의 글자 대비(WCAG AA) 검사
```

Node 22 이상이 필요합니다. 설치할 패키지는 없습니다.

## 티스토리에 적용하기

1. 블로그 관리 → 꾸미기 → 스킨 변경 → 현재 스킨을 **스킨 보관함에 저장** (되돌릴 지점)
2. **스킨 등록** → `dist/salieri-index-skin.zip` 업로드 → 적용
3. 꾸미기 → 스킨 편집 → 오른쪽 **스킨 옵션**을 다시 입력합니다. `index.xml`이 바뀌면 이전 값이 초기화됩니다.
   - 소개 문장, 한 줄 소개
   - GitHub · 포트폴리오 · velog · LinkedIn · X 주소, 이메일
   - 화면 모드, 글 목록 형태, **홈 길잡이**(3.1에서 새로 생김), 글 목차, 로고 이미지, 저작권 문구
4. 꾸미기 → 홈 화면 설정에서 커버 구성 (`인덱스`, `추천 글`, `갤러리`)
5. 꾸미기 → 모바일 → **티스토리 모바일웹 자동 연결 끄기** (모바일에서도 이 스킨이 보이도록)
6. (선택) 블로그 관리에서 글 하단 **"카테고리의 다른 글"** 표시를 끄면, 스킨의 썸네일 "같은 카테고리의 글"이 대신 나옵니다. 켜 두면 스킨이 티스토리 목록을 정리해서 보여 줍니다.

적용 전후 비교는 [docs/retention-baseline.md](docs/retention-baseline.md)를 참고하세요. 같은 방법으로 다시 재면 됩니다.
3.2의 근거(논문·업계 연구·GitHub)와 배포 전 확인할 것(목록 페이지 요청이 조회수에 잡히는지)은 [docs/retention-research.md](docs/retention-research.md)에 있습니다.
3.2는 스킨 옵션을 바꾸지 않았지만, 업로드 뒤 옵션 값이 그대로인지 한 번 확인하세요.
